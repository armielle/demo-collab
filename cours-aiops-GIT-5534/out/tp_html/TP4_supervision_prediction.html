Étape B2 — SARIMA : ajuster, prévoir, mesurer (40 min)¶

Protocole du cours : on ajuste sur les 21 premiers jours (576 heures) et on prévoit les 7 jours suivants (144 heures). Exogènes = harmoniques hebdomadaires (période 168 h). Deux contrôles obligatoires : MAE mesurée sur le test uniquement, comparée à deux bases naïves ; et tracé de l'intervalle de prévision.

# Modèle retenu : (2,0,1) x (1,0,1)_24, ajusté sur les 21 premiers jours
mod = SARIMAX(train.values, exog=X[:576], order=(2, 0, 1),
              seasonal_order=(1, 0, 1, 24),
              enforce_stationarity=False, enforce_invertibility=False)
res = mod.fit(disp=False, maxiter=300)
fc = res.get_forecast(144, exog=X[576:])
pred, ci = fc.predicted_mean, fc.conf_int(alpha=0.05)

# MAE honnête : mesurée sur le test uniquement
mae = float(np.mean(np.abs(pred - test.values)))
# Bases naïves : persistance 24 h (dernière journée du train, répétée)
mae_pers = float(np.mean(np.abs(
    np.tile(train.iloc[-24:].values, 6)[:144] - test.values)))
# Semaine précédente (les 6 derniers jours du train, répétés)
mae_sem = float(np.mean(np.abs(
    np.tile(train.iloc[-144:].values, 1) - test.values)))
gain = 100 * (1 - mae / mae_pers)
print(f"MAE SARIMA (test)            : {mae:.3f} pts CPU")
print(f"MAE persistance 24 h (test)  : {mae_pers:.3f} pts CPU")
print(f"MAE semaine précéd. (test)   : {mae_sem:.3f} pts CPU")
print(f"Gain vs persistance          : {gain:.1f} %")

Étape B3 — Modèle de panne, split temporel strict (30 min)¶

Split strictement temporel (fenetre < 2026-09-22 = train) : jamais de shuffle, aucune ligne du futur dans le train. Gradient boosting sur les fenêtres de 10 min, cible incident_30min.

from sklearn.ensemble import GradientBoostingClassifier
from sklearn.metrics import confusion_matrix

f = pd.read_csv("data/nosys_features.csv", parse_dates=["fenetre"])

         "cpu_amplitude", "h_sin", "h_cos"]
f = f.dropna(subset=feats + ["incident_30min"])

# Contrôle anti-fuite : refaire le modèle avec 'alarme' en entrée
# L'alarme vient des métriques brutes : on la ramène à la fenêtre de 10 min.
met = pd.read_csv("data/nosys_metriques.csv", parse_dates=["horodatage"])
met["fenetre"] = met.horodatage.dt.floor("10min")
alarme_fen = met.groupby(["serveur", "fenetre"]).alarme.max().reset_index()
f_leak = f.dropna(subset=feats + ["incident_30min"]).merge(
    alarme_fen, on=["serveur", "fenetre"], how="left")
f_leak["alarme"] = f_leak.alarme.fillna(0).astype(int)
tr_l, te_l = f_leak[f_leak.fenetre < cut], f_leak[f_leak.fenetre >= cut]
print("fenêtres d'alarme en test :", te_l.alarme.sum())
gbc_l = GradientBoostingClassifier(n_estimators=300, max_depth=4,
                                   learning_rate=0.06, random_state=5534)
gbc_l.fit(tr_l[feats + ["alarme"]], tr_l.incident_30min)
cm_l = confusion_matrix(te_l.incident_30min, gbc_l.predict(te_l[feats + ["alarme"]]))
print("avec 'alarme' en entrée :", cm_l.ravel(), "| précision fuite :",
      round(cm_l[1, 1] / (cm_l[1, 1] + cm_l[0, 1]), 3))

Étape B4 — Le budget d'alertes (20 min)¶

Le rappel seul ne décide rien : chaque fausse alerte coûte du temps d'astreinte. On classe les fenêtres de test par score décroissant et, chaque jour, on regarde les $k$ premières : c'est la courbe rappel en fonction du nombre d'alertes par jour.

In [12]:
# Score sur le test, puis rappel obtenu avec un budget de k alertes par jour
proba = gbc.predict_proba(te[feats])[:, 1]
y = te.incident_30min.values
n_jours = round(float((te.fenetre.max() - te.fenetre.min())
                      / pd.Timedelta(days=1) + 1.0 / 6), 2)
print("durée du test : %.2f jours" % n_jours)
ordre = np.argsort(-proba)                 # classement par score décroissant
pos_total = int(y.sum())
ks, recs = [], []
for k in range(1, 49):                     # k alertes par jour
    n_sel = min(int(round(k * n_jours)), len(y))
    recs.append(float(y[ordre[:n_sel]].sum() / pos_total))
    ks.append(k)
for k, r in zip(ks, recs):
    if k in (3, 5, 6, 12):
        print(f"{k:>2} alertes/jour -> rappel {r:.4f} "
              f"({round(r * pos_total):.0f}/{pos_total} incidents)")
k_op = next(k for k, r in zip(ks, recs) if r >= 0.60)
print(f"point d'opération : {k_op} alertes/jour -> rappel "
      f"{recs[ks.index(k_op)]:.3f} ; rappel max (top-k) : {max(recs):.3f}")

Lecture. À 5 alertes/jour on rattrape déjà l'essentiel de ce que les métriques savent voir ; au-delà, la courbe plafonne : les incidents restants n'ont aucun signal métrique — il faudra les journaux (séance 5). Si l'équipe n'accepte que 2 alertes/jour, le rappel chute nettement : le compromis à proposer au responsable d'exploitation se chiffre en incidents manqués (par jour) contre heures d'astreinte économisées.

# 1) Saturation du stockage : usage initial 40 %, +1,333 %/jour, seuil d'alerte 90 %
usage0, taux, seuil = 40.0, 1.333, 90.0
jours = (seuil - usage0) / taux
date_fin = pd.Timestamp("2026-10-01") + pd.Timedelta(days=jours)
print(f"jours avant 90 % : {jours:.1f} -> saturation le {date_fin:%d/%m/%Y}")

# 2) Disponibilité : prédictif évite 70 % des incidents
indispo_h = 11.3                      # heures d'indisponibilité mesurées / mois
heures_mois = 5760                    # 4 serveurs x 30 j x 24 h (parc visé)
indispo_restante = indispo_h * (1 - 0.70)
dispo = 100 * (1 - indispo_restante / heures_mois)
print(f"indispo {indispo_h:.1f} h/mois -> {indispo_restante:.2f} h avec 70 % évités")
print(f"disponibilité : {dispo:.3f} %")

Que décide l'exploitant lundi matin ? Le stockage atteint 90 % le 07/11/2026 (40 % → 90 % à +1,333 %/jour) : la rétention des logs doit être ramenée de 90 à 60 jours cette semaine (gain immédiat, sans achat) et une extension de 2 To est à commander sous quinzaine. Le SARIMA tient à ~3 pts CPU près sur 7 jours : la marge de capacité se pilote sur l'intervalle 95 % — on déclenche un scale-out horizontal si la borne haute dépasse 80 % trois nuits de suite. Le modèle de panne rattrape 62,5 % des incidents avec 5 alertes/jour ; couplé au prédictif (70 % d'incidents évités), la disponibilité passe à 99,941 %. Décisions : rétention courte, seuils d'alerte au point d'opération choisi en B4, budget d'astreinte figé à 5 alertes/jour.
