Étape B1 — Agréger les logs en sessions (machine, 10 min) (30 min)¶

Attention au piège de la qualité des données : compter bêtement les auth_reussie = False donne 4 828 « échecs » dont une partie n'est pas des authentifications (rotations de logs, sauvegardes) — filtrer d'abord, compter ensuite, et surveiller le volume de logs par machine (un agent tombé = fenêtres vides = aveugle pendant l'attaque).

Étape B2 — Features d'attaque + entropie de Shannon (30 min)¶

Sept features par session : echecs, taux_echec, echecs_consecutifs (rafale ininterrompue), utilisateurs (comptes testés en série), entropie (diversité des comptes testés, en bits), comptes_sensibles (échecs sur root, admin, inconnu-*), nuit (22 h - 06 h). Entropie : $H = -\sum_i p_i \log_2 p_i$, où $p_i$ est la part des essais portant sur le compte $i$.

SENSIBLES = {"root", "admin", "inconnu-1", "inconnu-2"}
g = logs.groupby(["machine", "fenetre"])
S = pd.DataFrame({
    "n_evenements": g.size(),
    "echecs": g["echec"].sum(),
    "succes": g["succes"].sum(),
    "utilisateurs": g["utilisateur"].nunique(),
    "comptes_sensibles": g.apply(
        lambda d: int(d.loc[d["echec"] == 1, "utilisateur"].isin(SENSIBLES).sum()),
        include_groups=False),
})
# Entropie de Shannon (base 2) des comptes testés dans la fenêtre
S["entropie"] = g["utilisateur"].apply(
    lambda u: float(shannon(list(pd.Series(list(u)).value_counts().values), base=2)))
# Rafale : plus longue séquence d'échecs consécutifs (ordre horodatage)
def max_run(d):
    e = d.sort_values("horodatage")["echec"].values
    best = cur = 0
    for v in e:
        cur = cur + 1 if v else 0
        best = max(best, cur)
    return best
S["echecs_consecutifs"] = g.apply(max_run, include_groups=False)
S["taux_echec"] = S["echecs"] / S["n_evenements"]
S["heure"] = S.index.get_level_values("fenetre").hour
S["nuit"] = ((S["heure"] < 6) | (S["heure"] >= 22)).astype(int)
S = S.reset_index()
print("sessions avec features :", S.shape, "(attendu : 10 000)")

# Étiquette (pour évaluer seulement) : la fenêtre d'attaque réelle
S["attaque"] = ((S.machine == "bdd-principal")

Étape B3 — IsolationForest : isoler l'anormal, juger par le classement (40 min)¶

Non supervisé, contamination=0.005 (a priori sur la fraction d'anomalies). On juge le détecteur par son classement : précision@N, pas étiquette binaire.

In [6]:
from sklearn.ensemble import IsolationForest

FEATS = ["echecs", "taux_echec", "utilisateurs", "entropie",
         "echecs_consecutifs", "comptes_sensibles", "nuit"]
X = S[FEATS].values
iso = IsolationForest(n_estimators=200, contamination=0.005,
                      random_state=5534, n_jobs=2)
iso.fit(X)
S["score_anomalie"] = -iso.decision_function(X)   # plus grand = plus anormal
S = S.sort_values("score_anomalie", ascending=False).reset_index(drop=True)
S["rang"] = np.arange(1, len(S) + 1)

print("rangs des 12 sessions d'attaque :",
      S.loc[S.attaque == 1, "rang"].tolist())
for n in (10, 30, 50):
    print(f"précision@{n} : {S.loc[:n - 1, 'attaque'].mean():.2f}")
print("rappel@30 :", S.loc[:29, "attaque"].sum() / S.attaque.sum())
print("par hasard, précision@30 serait : %.4f" % S.attaque.mean())

Étape B4 — Le détecteur supervisé (30 min)¶

Les incidents passés sont des étiquettes : sessions de la fenêtre d'attaque = 1, les 9 988 autres = 0. Split stratifié 50/50, graine 5534, class_weight équilibré — 6 positives en test.

from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import train_test_split
from sklearn.metrics import precision_score, recall_score

X = S[FEATS].values          # S est trié par rang : X et étiquettes alignés
y = S["attaque"].values
Xtr, Xte, ytr, yte = train_test_split(
    X, y, test_size=0.5, stratify=y, random_state=5534)
print("positives en test :", yte.sum())
rf = RandomForestClassifier(n_estimators=300, class_weight="balanced",
                            random_state=5534, n_jobs=2)
rf.fit(Xtr, ytr)
pred = rf.predict(Xte)
print(f"précision : {precision_score(yte, pred, zero_division=0):.2f} | "
      f"rappel : {recall_score(yte, pred):.2f}")

Lecture. Sur ce jeu, précision = rappel = 1,00 (6 positives en test) : le signal est si net que la forêt sépare parfaitement — mais méfiez-vous du 100 % : l'intervalle de confiance sur 6 positives est énorme, et un modèle parfait sur un jeu petit et propre échouera en production face à une attaque différente. Les quatre features de tête (comptes_sensibles, echecs, echecs_consecutifs, taux_echec) racontent la définition même d'un brute force. Règles et modèle fonctionnent en parallèle : la règle (5 échecs / 10 min) couvre le cas trivial, le modèle couvre le reste.

Étape B5 — Note d'incident (livrable, cellule markdown)¶

NOTE D'INCIDENT — INC-2026-1005-BDD

Résumé : campagne de brute force par authentification SSH contre bdd-principal, nuit du 05/10/2026, 02 h – 04 h (12 sessions de 10 min consécutives, regroupées en un seul incident).

Faits mesurés : 125 échecs d'authentification en 2 h (≈ 10,4 échecs par session, jusqu'à 15 consécutifs), zéro connexion réussie pendant la fenêtre, 100 % des échecs portent sur des comptes sensibles (root, admin, inconnu-1, inconnu-2), entropie des comptes testés 1,73 bit contre 2,22 en normal (petite liste ordonnée, signature robotisée), exclusivement en fenêtre de nuit.

Détection : remontée aux rangs 1–12 du classement IsolationForest (précision@10 = 1,0) et confirmée par la règle « 5 échecs / 10 min » — double canal, priorité maximale.

Action recommandée : ① bloquer la source réseau à pare-feu et verrouiller les comptes inconnu-* ; ② imposer l'authentification par clé + fail2ban (bannissement après 5 échecs) sur bdd-principal ; ③ vérifier l'absence de succès ailleurs dans le parc (corrélation inter-machines) ; ④ journaliser l'incident comme étiquette neuve pour réentraîner le détecteur supervisé (boucle d'amélioration), en pseudonymisant les identités hors note d'incident (privacy by design).
